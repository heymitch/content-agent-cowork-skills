# Strengthen Before Expand

## The Problem

When asked to "make content longer" or "expand this draft," AI defaults to adding more words without adding more insight. The result: longer content that says less per word.

**Wrong approach:** "How do I make this longer?"
**Right approach:** "How do I make this deeper?"

## The Framework

Before adding ANY words to a draft, complete these steps:

### Step 1: Identify the Core Claim

What is the ONE thing this post is arguing?

Write it in 10 words or less: _______________

If you can't, the post lacks focus. Don't expand it. Sharpen it.

### Step 2: Find the Weak Spots

Scan for these patterns that indicate shallow thinking:

**Vague Assertions:**
- "This really helped" → HOW did it help? What metric changed?
- "Significantly improved" → By what %? In what timeframe?
- "Many people struggle with" → WHO specifically? What's their situation?

**Missing Evidence:**
- Claims without numbers
- Principles without examples
- Lessons without stories

**Hedged Language:**
- "Can help" → Does it or doesn't it?
- "May improve" → Did it in your case?
- "Often leads to" → What's the actual rate?

### Step 3: Strengthen Each Weak Spot

Don't add new sections. Make existing sections hit harder.

**Before (weak):**
"AI tools can help with content creation."

**After (strengthened):**
"I used Claude to draft 47 LinkedIn posts last month. 12 outperformed my manually-written ones. The pattern: Claude drafted, I rewrote the first line. That combo beat either approach alone."

### Step 4: Cut Before You Add

If the strengthened version is still too short, you have permission to add. But first:

- Delete any sentence that doesn't advance the core claim
- Delete any transition that exists just to sound smooth
- Delete any conclusion that restates what you already said

Often, cutting creates the space you need. The post isn't too short. It's too padded.

## Strengthen vs Expand Decision Tree

```
Is the current draft < target length?
    │
    ├─ YES → Are there weak spots to strengthen?
    │         │
    │         ├─ YES → Strengthen them. Check length again.
    │         │
    │         └─ NO → Is there a missing supporting argument?
    │                  │
    │                  ├─ YES → Add ONE section with new evidence
    │                  │
    │                  └─ NO → The draft is done. Short is fine.
    │
    └─ NO → Done. Don't add anything.
```

## Examples: Strengthen vs Expand

### Example 1: Revenue Claim

**Original:**
"Our revenue grew after implementing this."

**Expanded (BAD):**
"Our revenue grew significantly after implementing this strategy. The implementation process took several months, and we saw improvements across multiple metrics. The team was very pleased with the results, and we continue to see positive trends."

*Problem: More words, zero new information.*

**Strengthened (GOOD):**
"Revenue grew 34% in 90 days. The only change: we stopped discounting."

*Difference: Specific number, specific timeframe, specific action.*

### Example 2: Learning Claim

**Original:**
"I learned a lot from this experience."

**Expanded (BAD):**
"I learned a tremendous amount from this experience. It was truly eye-opening and gave me many valuable insights that I continue to apply in my daily work. The lessons have been invaluable."

*Problem: Says "valuable" three ways without showing value.*

**Strengthened (GOOD):**
"I learned one thing: speed of feedback beats quality of feedback. We shipped weekly instead of monthly. Bugs doubled. Revenue tripled."

*Difference: ONE specific lesson, supported by specific outcome.*

## The Strengthening Checklist

Before finalizing any strengthened draft:

- [ ] Every claim has a number or specific example
- [ ] Every principle has a story that proves it
- [ ] No sentence exists just to add length
- [ ] The core argument is sharper than before
- [ ] A reader learns MORE per sentence, not less

## When Expansion IS Appropriate

Add new content ONLY when:

1. **New evidence exists** - You have a second story/data point that supports the claim
2. **Counter-argument needed** - The claim is so bold it needs preemptive defense
3. **How-to requested** - User specifically asked for actionable steps

Even then: Add ONE section. Strengthen everything else.

## Anti-Patterns to Avoid

**The Synonym Trap:**
Adding "synonyms" that don't add meaning
- "fast and speedy"
- "simple and easy"
- "clear and transparent"

**The Padding Paragraph:**
Transition paragraphs that exist to fill space
- "Now let's look at..."
- "Another important aspect is..."
- "Building on this idea..."

**The Conclusion Restate:**
Ending by saying what you already said
- "In summary..."
- "To recap..."
- "The key takeaway is..."

## Integration with Quality Pass

During the single quality pass:

1. **Pattern detection** → Remove AI tells
2. **RoR check** → Identify weak spots
3. **Strengthen** → Add specificity to weak spots
4. **Preserve thesis** → Never change the core argument
5. **Done** → No additional iteration
